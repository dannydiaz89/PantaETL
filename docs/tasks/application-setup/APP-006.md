- PostgreSQL service.
- Web service.
- Scheduler service.
- Worker service.
- Garbage collector service.
- Local persistent storage mounts.

## Notes / blockers

Development configuration now uses an ignored root `.env` file with a committed
`.env.example`. Direct Vite development and every direct service command read
that file; Compose consumes the same values and derives its internal PostgreSQL
connection hostname. No authentication secret or database credential is embedded
in Compose.

Validated with `docker compose --env-file .env.example config --quiet`,
`pnpm check`, and direct scheduler, garbage collector, and worker startup checks
using the example environment. Database-backed service health correctly returns
unavailable until PostgreSQL is configured; worker health returns OK.

The root workflow now provides `pnpm setup`, `pnpm generate`, and
`pnpm generate:check`. `pnpm stack:up` manages a loopback-only Docker PostgreSQL
instance, applies committed migrations, builds shared packages, and supervises
the local services with combined logs. `pnpm stack:status`, `pnpm stack:down`,
and the explicitly destructive `pnpm stack:reset` support that local stack.

Validated with `pnpm setup`, `pnpm generate`, `pnpm generate:check`, `pnpm
check`, `pnpm worker:check`, and a fresh temporary PostgreSQL database. The
temporary database received all migrations, web/scheduler/garbage collector/
worker started, and their health endpoints responded successfully.
